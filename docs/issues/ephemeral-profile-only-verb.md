# Ephemeral Profile-Only Hotspot Exploration Verb (`pew profile`)

- **Status:** Open
- **Governing contract:** [`docs/specs/spec.md`](../specs/spec.md) (`REQ-pew-profile-capture`, `REQ-pew-profile-attribution`, `REQ-pew-profile-report`, `REQ-pew-ab-output-ownership`, `REQ-pew-verb-defaults`, `REQ-pew-guidance`), [`docs/guidance.md`](../guidance.md)
- **Lands:** awaits triage

## Problem

When authoring or optimizing benchmarks before locking committed baselines, operators and agents need to capture CPU and allocation profiles, inspect hotspots, fix engine bottlenecks, commit the clean code, and only then run a full statistical `pew run --profile=cpu,alloc ./...` pass on the clean tree.

Today `pew` couples single-side diagnostic capture (`REQ-pew-profile-capture`) exclusively to `pew run`, and two-side diagnostic capture to `pew ab`:

- `pew run --profile=cpu,alloc` requires an admitted `--count >= 1` stored `.txt` recording in `<bench-dir>` (`./benchmarks` by default) to attach `.profiles/sha256/` CAS blobs and `.profiles/executables/` binaries against (serving an existing recording only when valid, and executing default `--count=10` statistical passes at `--benchtime=1s` whenever a benchmark is unrecorded or stale — i.e., on every edit during pre-baseline hotspot tuning), while printing only `profiled <pkg>.<Benchmark> <kind>` without rendering hotspot tables. Running `pew run` during iterative hotspot tuning either burns 10x statistical measurement time on unoptimized code whose baseline will immediately become stale after the fix, or forces callers to pass `--count=1 --benchtime=1x --bench-dir=<tmp>` and manually locate raw SHA-256 blobs for `go tool pprof`.
- `pew ab --profile` supports non-retained temporary diagnostics when `--out` is omitted (`spec.md` §6.2), but requires comparing the working tree against a second git ref (`HEAD` or an explicit ref) and still executes statistical A/B sample passes on both sides, failing or doing redundant work when a benchmark is newly added or only single-side hotspot attribution is needed.
- Existing open issues ([`single-recording-show-verb`](single-recording-show-verb.md), [`profile-source-line-attribution`](profile-source-line-attribution.md), [`profile-setup-vs-timed-loop-attribution`](profile-setup-vs-timed-loop-attribution.md), and [`status-and-stat-bench-and-profile-top-filters`](status-and-stat-bench-and-profile-top-filters.md)) cover inspecting and attributing *stored* or *compared* profiles, not ephemeral pre-baseline diagnostic capture without statistical `--count` runs or `<bench-dir>` I/O.

## Resolution Scope

1. Add an ephemeral, store-free diagnostic verb (for example `pew profile [packages]`) registered in `docs/specs/spec.md` §12 (`REQ-pew-verb-defaults`) and `docs/guidance.md` (`REQ-pew-guidance`) that executes only the single-subject contained diagnostic passes of `REQ-pew-profile-capture` (`cpu`, `alloc`, or default `cpu,alloc` in separate count-1 `identity-only` processes) with zero statistical `--count` sample runs and zero reads or writes under `<bench-dir>` (including bypassing `<bench-dir>/vouches` reads during engine construction, matching store-free `REQ-pew-verb-defaults` rules where `--bench-dir` and `--vouch` are omitted).
2. Support `--bench` (`go test -bench` hierarchical regexp selection), `--profile` (`cpu|alloc|cpu,alloc`, default `cpu,alloc`), `--profile-benchtime` (default `1s`, duration or `Nx`), `--pin`, `--strict`, `--top`, line-level source hotspot attribution (coordinating with [`profile-source-line-attribution`](profile-source-line-attribution.md) and [`profile-setup-vs-timed-loop-attribution`](profile-setup-vs-timed-loop-attribution.md)), `--json`, and an optional `--out <dir>` flag retaining the built test executables and `.pb.gz` profile artifacts for interactive `go tool pprof` inspection under `REQ-pew-ab-output-ownership`-equivalent path refusal (refusing `--out` paths that traverse symlink components or overlap any module's recording store `<bench-dir>` or build-selected source/PGO/module inputs); without `--out`, temporary executables and profile files are cleaned up on exit exactly as in `pew ab` without `--out`.
3. Enforce the same containment, process-group lifecycle, quiesce/pin reporting, and exact-source attribution rules (`REQ-pew-profile-attribution`, `REQ-pew-profile-report`) as `pew run --profile`, while explicitly reporting non-retention so an ephemeral `pew profile` run can never be mistaken for a stored provenance baseline.
